# Phase 1 — Database & migrations

## Scope
Define the SQLAlchemy 2.0 async data layer and the initial Alembic migration matching `BACKEND_BUILD_PLAN.md` §6. Seed the static reference data (languages, phrase categories, starter phrases).

## Deliverables

### 1. Base & session
- `app/db/base.py`:
  - `DeclarativeBase` subclass `Base` with naming convention for constraints (`ix_%(column_0_label)s`, `uq_%(table_name)s_%(column_0_name)s`, etc.) — required for safe Alembic autogeneration.
- `app/db/session.py`:
  - `engine = create_async_engine(settings.database_url, pool_pre_ping=True)`.
  - `AsyncSessionLocal = async_sessionmaker(engine, expire_on_commit=False)`.
  - Async generator `get_session()` for FastAPI DI.

### 2. Models (one file per aggregate under `app/db/models/`)
- `user.py` → `User`, `UserSettings` (1:1).
- `language.py` → `Language` (PK `code`, e.g. `en`, `hi`, `te`, `th`).
- `phrase.py` → `PhraseCategory`, `Phrase`, `PhraseTranslation`.
- `conversation.py` → `Conversation`, `Message`.
- `favorite.py` → `Favorite`, `Recent`.

Use SQLAlchemy 2.0 `Mapped[...]` / `mapped_column` syntax. Timestamps default to `func.now()`. Soft-delete columns: `deleted_at: Mapped[datetime | None]`.

### 3. Alembic
- `alembic init -t async alembic` then edit `alembic/env.py` to use the async engine and `Base.metadata`.
- `alembic.ini` reads URL from env, not the ini.
- `0001_initial.py` — autogenerated then hand-reviewed. Must include:
  - All tables from plan §6.
  - All indexes listed in plan §6.
  - `pg_trgm` extension + GIN trigram indexes on `messages.source_text`, `messages.translated_text` (used by /conversations search).

### 4. Seed script
`scripts/seed_phrases.py`:
- Idempotent (upsert on PKs / unique keys).
- Seeds 4 rows in `languages` (en, hi, te, th) with flag emoji + capability flags from §5.
- Seeds 5 rows in `phrase_categories` (restaurants, directions, transport, shopping, emergencies).
- Seeds 30 rows in `phrases` (6 per category) — copy text from `reference_app/FEATURES_AND_FLOWS.md` §5.2.
- Run via `uv run python -m scripts.seed_phrases`.

### 5. Repositories (`app/repositories/`)
Thin async data-access classes — no business logic. One per aggregate. Each takes an `AsyncSession` in its constructor and exposes typed methods (e.g. `ConversationRepo.list_for_user(user_id, limit, cursor)`).

## Verification
- `uv run alembic upgrade head` on a fresh Postgres creates every table + every index in plan §6.
- `uv run python -m scripts.seed_phrases` inserts the 4 languages + 5 categories + 30 phrases.
- Re-running seed is a no-op (idempotent).

## Out of scope
Routers, services, auth, HF integration.
